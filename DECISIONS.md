# Engineering Decisions & Design Rationale

This document details the architectural choices, pricing models, and integration decisions made during the construction of the Agent-First Transcription API.

---

## 1. Architectural Decisions

### FastAPI & BackgroundTasks
* **Choice**: We implemented the service using **FastAPI** coupled with native **`BackgroundTasks`** and a local **SQLite** database.
* **Alternative Considered**: Celery with Redis/RabbitMQ.
* **Trade-off**: While Celery is standard for massive scale, it introduces a significant operations footprint (running and maintaining a Redis cluster/broker and multiple worker processes). Since this service runs on a single node and short-form videos take 10–60 seconds, FastAPI’s in-memory background worker combined with SQLite database state persistence delivers a robust, zero-configuration solution that deploys easily inside a single Docker container.
* **Job Flow**:
  1. `POST /v1/transcribe` writes a `pending` status row to SQLite and queues a background thread.
  2. The background thread updates the status to `processing` and runs the transcription pipeline under a thread lock to ensure accurate job-level cost tracking.
  3. Upon success, results are serialized to JSON in SQLite and marked `completed`. If any stage fails, the traceback is logged and status set to `failed`.

### SQLite DB Schema
* To support multi-tenant API calls, we implemented three simple relational tables:
  * `APIKey`: Tracks active clients, rate limits, and billing balances.
  * `TranscriptionJob`: Tracks state, inputs, outputs, and stack traces of failures.
  * `UsageLog`: Saves granular token/time metrics per transcription job for auditing.

## 2. Pricing & Sustainability Model

### Upstream Costs
Our pipeline costs break down as follows:
1. **Whisper Tiny (Local)**: $0.00
2. **Chirp 3 Diarization**: $0.016 / minute (Speech-to-Text v2 pricing)
3. **Gemini 2.5 Flash**: $0.30 per 1M input tokens / $2.50 per 1M output tokens (approx. $0.01–$0.02 per short video)
4. **Gemini 2.5 Pro Fallback**: $1.25 per 1M input tokens / $10.00 per 1M output tokens (approx. $0.05–$0.08 per video)

* **Typical Raw Cost**: **$0.02 - $0.08 per video**

### Competitor Pricing
* **Deepgram (Nova-2)**: ~$0.0043 to $0.0150 per minute.
* **AssemblyAI**: ~$0.012 to $0.015 per minute.
* **Google Cloud STT**: ~$0.016 to $0.024 per minute.

### Our Pricing Strategy
Because our pipeline includes **multi-stage diarization (Chirp 3), advanced translation, and on-screen text extraction (Gemini)**, it is a high-value structured transcription product rather than raw voice-to-text.
* **Billing Unit**: We charge a flat **$0.12 per minute** (or $0.002 per second) of audio processed, with a minimum billing duration of 15 seconds per file.
* **Profitability**: At $0.12/minute:
  * A 30-second video ($0.06 billing) running on Gemini Flash (total raw cost ~$0.018) yields a **70% profit margin**.
  * A 30-second video falling back to Gemini Pro (total raw cost ~$0.058) still achieves a break-even/slight profit.
* **Usage tracking**: Rather than a hidden subscription, we expose this usage transparency programmatically through `GET /v1/usage`, allowing agents to monitor their budgets.

## 3. Agent-First Usability & Error Design

### API Key Rate Limiting
* We implement a token-bucket rate limiter.
* When rate limits are hit, we do not simply drop connections. We respond with a standard `429 Too Many Requests` status, insert a `Retry-After: <seconds>` HTTP header, and output a detailed machine-readable error body explaining:
  * The current limit.
  * How many seconds the agent must sleep before retrying.
  * A clickable documentation URL.

### Machine-Readable Actionable Errors
Upstream model failures (e.g. Gemini quota limits, Chirp 3 failures) are intercepted and translated into structured errors:
* If Gemini returns a 429, we surface `UPSTREAM_RATE_LIMIT` and recommend a backoff.
* If a file exceeds size limits, we return `FILE_TOO_LARGE` with a suggestion to strip video tracks and upload audio only.

### Model Context Protocol (MCP) Integration
* We built a dedicated MCP server in `app/mcp_server.py` using the official `mcp` SDK.
* This allows LLMs (such as Claude, ChatGPT, or Cursor) to automatically discover the transcription capability as a tool when connected, enabling seamless agent tool-calling.

### SDK Autogeneration
Because we use FastAPI, the entire API schema is strictly defined. A client Python SDK can be autogenerated directly from `/openapi.json` using `openapi-generator-cli`:
```bash
npx @openapitools/openapi-generator-cli generate -i http://localhost:8000/openapi.json -g python -o sdk/python
```
This is fully documented in `llms.txt` so agents can build their own clients dynamically if needed.
